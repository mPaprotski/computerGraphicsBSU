# Лабораторная №2 — вариант 7

Глобальная пороговая обработка (ручной порог, Оцу) и низкочастотная фильтрация (усредняющий фильтр, Гаусс). Go 1.22+, только стандартная библиотека.

## Запуск готового файла в Windows

`lab2.exe` — готовая сборка для Windows x64. Запустите двойным щелчком и откройте http://127.0.0.1:8080 в браузере. Оставьте окно консоли открытым на время работы; для остановки нажмите Ctrl+C или закройте его. Установка Go не нужна: интерфейс и тестовые изображения встроены в файл.

## Запуск из исходников

Из папки `Lab_2`:

```sh
go run ./cmd/server
```

Откройте http://127.0.0.1:8080. Другой порт: `go run ./cmd/server -addr 127.0.0.1:8081`.

```sh
go test ./...
go vet ./...
go build -o lab2 ./cmd/server
```

Ресурсы и тестовые PNG встроены в исполняемый файл. Выберите файл или пример, метод, параметры, нажмите «Обработать изображение». Результат скачивается в PNG. Ограничения: PNG/JPEG до 12 МиБ, 4 млн пикселей, сторона до 4096. Сервер обрабатывает файлы в памяти.

## Алгоритмы

Яркость Y = round(0.299R + 0.587G + 0.114B). Для пороговых методов используются RGB без учёта прозрачности: демонстрируйте непрозрачные изображения.

Ручной порог: Y < T → 0; Y ≥ T → 255. Один порог для всех пикселей, требуется подбор под нужный объект.

Оцу: гистограмма 256 уровней, максимум n₀n₁(μ₀−μ₁)² по всем разбиениям. Возвращается первый уровень белого класса, что согласовано со сравнением ≥. При равенстве максимумов выбирается первый. Для однотонного изображения порог равен его яркости. Время O(W·H + 256).

Усредняющий фильтр: квадратное ядро k×k с весами 1/k². Подавляет шум, размывает границы.

Гаусс: веса пропорциональны exp(−(x²+y²)/(2σ²)), нормированы до суммы 1. Центр имеет больший вес. С ростом σ полезно увеличить окно, иначе оно обрезает гауссиану.

Фильтры используют два одномерных прохода: O(W·H·k). На границах повторяется ближайший пиксель. Альфа обрабатывается в предумноженном представлении, затем восстанавливается RGB. Гамма RGB не линеаризуется.

## База тестовых изображений

Четыре синтетических PNG 480×320 лежат в `web/samples` и доступны в интерфейсе.

| Пример | Проверка и ожидаемый результат |
|---|---|
| bimodal.png | Два класса с небольшим шумом. Ручной T=220 теряет объект, Оцу разделяет классы автоматически. Ручной T=128 тоже корректен. |
| rare.png | Маленький тёмный квадрат на градиентном фоне. Ручной T=80 выделяет квадрат; Оцу разделяет преобладающий фон. |
| noise.png | Цветной шум, края, тонкие линии. Сравните фильтры при k=5, σ=1.4 и k=15, σ=4. Шум уменьшается, детали теряются. |
| lighting.png | Неравномерное освещение: яркости объекта и фона перекрываются. Оба глобальных метода не могут корректно выделить весь объект. |

Оцу автоматически выбирает глобальный порог, но правильно подобранный ручной порог может повторить его результат. Сравнение показывает преимущество автоматизации перед неудачным ручным выбором, а также преимущество ручного порога для конкретного малого объекта.

На защите покажите оригиналы и результаты, объясните параметры, потерю деталей при сглаживании и ограничения глобального порога. Базу можно дополнить своими фотографиями и сканами. Критерии задания: корректность 50 баллов, изображения 20, пояснения 30.
